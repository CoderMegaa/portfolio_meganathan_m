01 / THE BIG PICTURE

Purpose & perspective.

This integration connects a Flutter-based executable application with Tally installed on the user’s system. The application retrieves Tally data through XML requests and transfers it to the SAA Sublimation Django application through APIs, where the data is processed, stored, and displayed in the web interface.

THE OBJECTIVE

Establish a working data-transfer path between a locally installed accounting application and a connected business web application.

The business workflow

  1. 01Tally on the user’s system
  2. 02Flutter executable & XML
  3. 03Django REST APIs
  4. 04Process, store & display
02 / CORE FUNCTIONALITY

Built around real operations.

01

Local Tally connection

Use a Flutter-based executable to connect with Tally on the user’s system.

02

XML data retrieval

Send XML requests to retrieve the required Tally data for the integration workflow.

03

API-based transfer

Transfer the retrieved accounting data to the Django application through APIs.

04

Web processing & display

Process and store the transferred data, then make it available through the web application.

03 / UNDER THE HOOD

How it comes together.

Desktop integration

Flutter and Dart implement the executable side of the integration. XML is used for requests to Tally.

Backend & storage

Python, Django, REST APIs, and PostgreSQL handle the receiving, processing, and storage side of the workflow.

Browser interface

HTML, CSS, JavaScript, and Bootstrap support the web interface used to display the transferred data.

MY CONTRIBUTION

Hands-on ownership.

I developed the core integration process and led the primary development and integration work in a two-member setup, coordinating frontend UI work with a junior developer.

Business value

Provides a defined connection between locally held accounting data and the business web application, allowing the retrieved information to be used in the connected system.
